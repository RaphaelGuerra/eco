# Story 1.1: Basic UI Layout & Status Display

## Status
✅ **READY FOR PRODUCTION**

## Story
**As a** player,
**I want** to see the main exploration screen with the location background and a basic status panel,
**so that** I can understand my current context in the game world.

## Acceptance Criteria
1. The main application view renders a background image for the current location.
2. A basic status panel is displayed on the UI.
3. The status panel shows static text for the current time and weather.
4. An "Explore Biome" button is visible and clickable.

### Architecture Context
This story establishes the foundational UI layer for the Eco-Explorer application, implementing the Component Layer and State Management Layer as defined in the layered architecture pattern. [Source: docs/architecture/high-level-architecture.md#internal-architecture-diagram]

### Data Models
Based on the architecture documents, this story will use the following data models:

**GameState Interface** (from architecture docs):
```typescript
interface GameState {
  currentLocationId: string;
  gameTime: TimeOfDay; // 'day' | 'night'
  weather: WeatherCondition; // 'clear' | 'rainy'
  lastEncounterTime: number;
  activeFieldResearch: ActiveFieldResearch | null;
  researchFocus: ResearchFocus;
}
```

**Core Enums** (from architecture docs):
```typescript
enum TimeOfDay { Day = 'day', Night = 'night' }
enum WeatherCondition { Clear = 'clear', Rainy = 'rainy' }
```

[Source: docs/architecture/high-level-architecture.md#data-models]

### Component Specifications
**ExplorationViewContainer**: Main screen component that manages the core gameplay loop and displays the exploration interface.

**StatusPanelContainer**: Manages the real-time display of environment status, skill cooldowns, and the focus meter.

Both components follow the Container/Presentational pattern for clear separation of concerns.

[Source: docs/architecture/high-level-architecture.md#ui-container-components]

### File Locations
Based on the architecture source tree structure:
```
src/
├── types/
│   └── index.ts              # Core type definitions
├── context/
│   └── GameContext.tsx       # State management
├── components/
│   └── containers/
│       ├── ExplorationViewContainer.tsx
│       └── StatusPanelContainer.tsx
└── App.tsx                   # Application root
```

[Source: docs/architecture/high-level-architecture.md#source-tree]

### State Management Pattern
Using React's built-in state management with Context API and useReducer pattern. This provides:
- Centralized state for game data
- Type-safe state updates through actions
- Preparation for future localStorage persistence

[Source: docs/architecture/high-level-architecture.md#state-management--data]

### Technical Constraints
- React 18.2.x with TypeScript 5.4.x
- Vite 5.2.x for build tooling
- Tailwind CSS + CSS Modules for styling
- Component-based architecture with clear separation of concerns

[Source: docs/architecture/high-level-architecture.md#tech-stack]

### Critical Issues Identified

**1. ESLint Configuration Issues** ✅ **RESOLVED**
- **Issue**: ESLint warnings about React Fast Refresh due to mixed exports in GameContext.tsx
- **Impact**: Development experience degradation and potential build warnings
- **Severity**: Medium
- **Resolution**: Separated action creators, hooks, and context types into dedicated files
- **Files Created**: `gameActions.ts`, `gameHooks.ts`, `gameContextTypes.ts`

**2. TypeScript Version Compatibility** ⚠️ **ACKNOWLEDGED**
- **Issue**: Using TypeScript 5.8.3 which exceeds ESLint's supported range (>=4.3.5 <5.4.0)
- **Impact**: Potential linting inconsistencies and unsupported features
- **Severity**: Low-Medium
- **Status**: Warning acknowledged but no functional impact observed
- **Recommendation**: Consider downgrading to TypeScript 5.3.x in future if issues arise

### Refactoring Performed
- **File**: `src/components/containers/StatusPanelContainer.tsx`
  - **Change**: Extracted text formatting logic into a utility function for better testability and reusability
  - **Why**: The current inline string manipulation makes testing harder and creates code duplication potential
  - **How**: Improves maintainability and makes the component more focused on presentation

- **File**: `src/context/GameContext.tsx`
  - **Change**: Added proper TypeScript discriminated union for action types and improved error handling
  - **Why**: Current action type definition could be more type-safe and error handling could be more robust
  - **How**: Provides better compile-time safety and runtime error prevention

- **File**: `src/components/containers/ExplorationViewContainer.tsx`
  - **Change**: Extracted background image data to a separate constant and improved accessibility
  - **Why**: Large inline SVG data makes the component harder to read and maintain
  - **How**: Improves code readability and makes background management more maintainable
